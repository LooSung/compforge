# Plugin evals — 2026-11-16

`claude plugin eval` on Claude Code 2.1.311, against the v1.7.0 release
candidate. Every case is read-only (Read, Glob, Grep, Skill) and runs once, so
this is a smoke signal, not a distribution. LLM graders vote three times.

Reproduce from the repository root:

```bash
claude plugin eval . --runs 3                               # with/without plugin
claude plugin eval . --model haiku --ablation none --runs 3 # one model, plugin only
```

## With and without the plugin (harness default model)

| Case | With plugin | Without plugin |
|---|---|---|
| review-pasted-diff | 1.0 | 0.5 |
| consult-derived-state | 1.0 | 0.5 |
| craft-vague-request | 1.0 | 0.0 |

## Smaller models (plugin only)

| Case | Haiku | Sonnet |
|---|---|---|
| review-pasted-diff | 0.5 | 0.0 |
| consult-derived-state | 1.0 | 1.0 |
| craft-vague-request | 1.0 | 1.0 |

Both review failures were judge disagreements, not missing behavior. The Haiku
and Sonnet responses each used the P1/P2/P3 format at base `pasted` and named the
effect-derived total, the ignored `error`, and the non-keyboard Checkout `<div>`.

## Limits

- One run per case; scores can move between runs.
- The harness default model is not recorded in the eval output.
- Graders are LLM judges (Haiku by default, Sonnet for the re-runs above). A
  failing vote was read against the response before it was recorded here.
- Codex CLI and Cursor Agent were not exercised by these evals.
